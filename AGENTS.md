# Working on this project

Read [docs/START-HERE.md](docs/START-HERE.md) before project work. Read the linked documents relevant to the task; do not assume chat memory is the project record.

- The JRPG is paused for implementation as of 2026-10-06. Planning and documentation can continue when requested. A request to discuss or record an idea is not a request to restart development or spend credits.
- Evaluate existing solutions before substantial custom implementation: follow [the reuse-first policy](docs/production/reuse-first.md).
- Preserve the freely rotating 3D camera and intended connected, separately loaded zones. The preview village is a prototype, not an approved settlement layout.
- Distinguish user decisions, assistant proposals, verified results and untested assumptions. A concept image is not proof of in-engine quality or performance.
- Check the actual repository, engine configuration and current task before acting on older plans. New explicit user instructions take precedence; record changed decisions rather than silently rewriting history.
- Keep work proportional: documentation-only changes need a diff/link review, not an Android build or gameplay test. Code and asset changes need validation appropriate to the affected behaviour.
- At a handoff, update the relevant durable document and the status/next-step section in START-HERE. Include what changed, what was verified and what remains uncertain. Never claim remote saving without verifying it.
- Keep credentials and private account/device details out of this public repository. Preserve asset provenance and licences.
